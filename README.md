# КУТ БИЛИМ 1.0

Мобильное приложение Expo для Android и iOS и API Django с одобрением регистрации администратором.

## Структура

- `frontend/src/features/auth` — вход, регистрация, выбор фото.
- `frontend/src/features/profile` — профиль после входа.
- `frontend/src/shared` — API и оформление платформы.
- `backend/config` — настройки и маршруты Django.
- `backend/accounts` — пользователи, регистрация и вход.
- `backend/administration` — API управления заявками и права администратора.
- `frontend/src/features/admin` — мобильный дашборд администратора.

Новые функции добавляйте отдельными папками в `features` и отдельными Django-приложениями.

## Backend

```sh
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver 0.0.0.0:8000
```

Админка доступна только по секретному пути: http://127.0.0.1:8000/u8f93hiuvfbviug7f8g584gifoeugf9re7gfugieurfg87/ (адрес `/admin/` отдаёт 404). На сервере задайте свой путь через переменную окружения `DJANGO_ADMIN_PATH`. При создании администратора укажите Gmail, username и уникальный учебный номер. В разделе пользователей выберите ожидающие заявки и действие «Одобрить выбранные заявки». Отклонение отключает аккаунт и удаляет токен. Уведомление по электронной почте не настроено: заявки поступают непосредственно в админку.

## Мобильное приложение

```sh
cd frontend
npm install
npx expo install --fix
cp .env.example .env
npm start
```

В `.env` укажите `EXPO_PUBLIC_API_URL=http://IP_КОМПЬЮТЕРА:8000/api/auth`. Телефон и компьютер должны быть в одной сети. Добавьте IP компьютера в переменную окружения backend `DJANGO_ALLOWED_HOSTS` (список через запятую). По умолчанию Android Emulator использует `10.0.2.2`, iOS Simulator — `localhost`. После изменения `.env` перезапустите Expo. Для запуска на устройстве нужна версия Expo Go, совместимая с SDK 55, либо собственная development build.

Логотип подключён из `frontend/assets/Kyrgyzstan_Border_Service.svg.webp` в `src/shared/branding.ts` и отображается по центру экрана входа и регистрации.

## Регистрация

Обязательные поля: категория («Офицерлер» или «Прапорщиктер жана сержанттар»), учебный номер, воинская часть, фото, Gmail, пароль и подтверждение. Пароль добавлен, чтобы пользователь мог войти после одобрения. Сервер проверяет изображение и размер до 5 МБ, хеширует пароль и создаёт неактивный аккаунт. Одобрение открывает доступ; токен хранится в SecureStore. Фотографии не публикуются через открытый media URL.

## Развёртывание

Для публичного сервера задайте `DJANGO_DEBUG=0`, случайный `DJANGO_SECRET_KEY` и `DJANGO_ALLOWED_HOSTS`. Используйте HTTPS, PostgreSQL, закрытое хранилище фото и production WSGI-сервер. Текущие SQLite и Django runserver предназначены для локальной разработки. Перед публичным запуском настройте резервные копии и общую систему ограничения запросов для нескольких процессов.

Использованы официальные сведения о совместимости [Expo SDK 55](https://expo.dev/changelog/sdk-55) и [Django 5.2 с Python](https://docs.djangoproject.com/en/5.2/releases/5.2/).

## Дашборд администратора в приложении

Войдите через «Кирүү» с email и паролем уже созданного `createsuperuser`. Для входа администратора разрешён email любого домена; регистрация пользователей требует Gmail. Суперпользователь видит общую главную страницу; заявки доступны через «Башкаруу панели» → «Өтүнмөлөр». Список содержит фото, Gmail, учебный номер, воинскую часть и дату регистрации. Фильтры: «Күтүүдө», «Ырасталган», «Четке кагылган», «Баары».

«Ырастоо» активирует аккаунт. «Четке кагуу» означает «Отклонить»: отключает вход и отзывает текущую сессию. Решение можно изменить через фильтр соответствующего статуса. Действия требуют подтверждения. Обновление списка — потянуть вниз; следующие страницы — «Дагы көрсөтүү». Доступ к API и фото заявителей есть только у суперпользователя. Изменения схемы базы данных не требуются.

## Тесты по темам

В «Командирдик даярдоо» и «Өз алдынча даярдануу» внутри каждой темы доступны «Тест кошуу» для администратора и «Тест өтүү» для пользователя. Администратор задаёт название, время в минутах и вопросы: 2–10 различных вариантов ответа, один правильный. Каждый тест привязан к конкретной теме. Темы разделены по разделу, категории и месяцу. Ранее созданные месячные тесты сохранены в отдельных темах с названиями этих тестов; история попыток сохранена.

Сервер перемешивает вопросы и варианты для каждой попытки, не передаёт правильные ответы клиенту, сохраняет каждый выбранный ответ и рассчитывает `правильные ответы / все вопросы × 100`. При окончании времени учитываются только ответы, сохранённые до серверного дедлайна. Выход, обнаруженный скриншот и возврат к незавершённому тесту после перезапуска дают провал и 0%. Одна активная попытка на аккаунт. Клиент отправляет сигнал активности раз в 5 секунд; отсутствие связи более 30 секунд проваливает попытку при следующем обращении к серверу.

Прохождение разрешается только после включения нативной защиты экрана: Android 14+ или iOS 13+. В браузере прохождение закрыто; администратор может создавать тесты. Модуль `expo-screen-capture` указан в зависимостях; выполните `npm install` при доступном npm и пересоберите свою development build. Expo Go должен включать совместимый модуль. В этой среде установка модуля не выполнена из-за отсутствия доступа к npm. Защита текста реализована отсутствием выделения и полей редактирования на экране теста.

ОС может заблокировать снимок без события о попытке. Провал происходит при полученном событии `onScreenshot`; гарантировать обнаружение каждого нажатия кнопок снимка или съёмки другим устройством нельзя. Нужна проверка на физических Android/iOS: блокировка снимка и записи экрана, переход в фон, системная кнопка «Назад», принудительное закрытие, восстановление и таймер. Поведение SDK: https://docs.expo.dev/versions/v55.0.0/sdk/screen-capture/.

Проверки: `python manage.py test accounts administration`, `npm run typecheck`, `npm run test:quiz-protection`. Тесты адаптера используют подмену нативного модуля и не заменяют проверку на устройстве.

## Түзөтүү (Поправка)

В «Дене-тарбия даярдыгы» → «Түзөтүү (Поправка)» пользователь добавляет возраст, высоту в метрах, номер одежды или «Спорт кийими», наличие оружия и экипировки и номер упражнения. Кнопка «Түзөтүүнү чыгаруу» сохраняет запись в аккаунте на сервере; список доступен после повторного входа. Записи других пользователей не показываются. Числовые коэффициенты поправки не рассчитываются: нормативные таблицы не заданы.



Миграция: `cd backend && .venv/bin/python manage.py migrate`. Тесты: `.venv/bin/python manage.py test accounts.test_corrections`.

## Жеке машыгуу планы

«Дене-тарбия даярдыгы» → «Жеке машыгуу планы»: «Күн кошуу» создаёт следующий день (Күн 1, Күн 2…) и открывает его. «Кошуу» добавляет пару полей с серыми подсказками «Эмне кылуу» и «Канчага чейин». Можно добавить несколько строк, убрать лишние и нажать «Сактоо». Сохранение возвращает к списку дней; при повторном открытии данные показываются без полей и кнопок редактирования. «Өзгөртүү» включает редактирование, «Жокко чыгаруу» возвращает сохранённые значения. Дни и упражнения сохраняются на сервере отдельно для каждого аккаунта. Возврат без «Сактоо» не сохраняет изменения строк.

Миграция: `cd backend && .venv/bin/python manage.py migrate`. Проверки: `.venv/bin/python manage.py test accounts.test_personal_plan` и `cd frontend && npm run typecheck`.

## Окуу курстары

Администратор открывает «Окуу курстары», нажимает «Кошуу», вводит название и сохраняет. Новый раздел сразу открывается. Внутри «Кошуу» создаёт вложенный подраздел; материалы добавляются только внутри подраздела второго уровня. В подразделе второго уровня «Материал кошуу» позволяет сохранить текст, ссылки и несколько файлов (фото, видео, документы). Файлы открываются через временные ссылки, доступные одобренным пользователям. Пользователи видят разделы и материалы без кнопок создания. «Артка» возвращает на предыдущий уровень, «Жаңылоо» обновляет материалы.

Миграция: `cd backend && .venv/bin/python manage.py migrate`. Проверки: `.venv/bin/python manage.py test accounts.test_courses` и `cd frontend && npm run typecheck`.

## Курстун башчысы

При регистрации в «Категория» доступна роль «Курстун башчысы» (после одобрения администратором). В «Окуу курстары» курстун башчысы создаёт курсы через «Кошуу» так же, как администратор, и видит кнопку «Менин курстарым». Там список его курсов; внутри курса четыре раздела:

- «Темалар» — темы курса: добавление, переименование, удаление; нажатие на тему открывает её материалы с «Материал кошуу».
- «Материалдар» — все материалы курса по темам.
- «Колдонуучулар» — записавшиеся пользователи с учебным номером, Gmail, воинской частью и датой записи.
- «Тесттер» — тесты курса и кнопка «Кошуу». При создании указываются название, время, вопросы и дедлайн (КК.АА.ЖЖЖЖ СС:ММ, время устройства). После дедлайна тест не начинается, а начатая попытка завершается не позже дедлайна.

Курстун башчысы изменяет только свои курсы; администратор — все. Обычный пользователь открывает курс и нажимает «Курска жазылуу» (повторное нажатие отменяет запись); тесты курса доступны только записавшимся через «Тесттер →» и используют ту же защиту, что и остальные тесты. Курс с тестами нельзя удалить, пока тесты не удалены.

Миграция: `cd backend && .venv/bin/python manage.py migrate`. Проверки: `.venv/bin/python manage.py test accounts.test_courses` и `cd frontend && npm run typecheck`.

## Веб-сайт (frontend-web)

Папка `frontend-web` — сайт на Vite + React: главная страница с кнопками «Android (APK)» и «iOS» и кнопкой «Кирүү» в правом верхнем углу. Через неё суперпользователь входит в веб-дашборд: обзор, «Өтүнмөлөр» (ырастоо / четке кагуу, фото, фильтры, поиск), «Командирдик даярдоо» (те же функции, что у администратора в приложении: категория → полугодие → месяц → предметы → темы → материалы с текстом, ссылками и файлами; тесты предмета — создание, изменение, удаление), «Колдонуучулар» по аскер бөлүктөрү и «Тест жыйынтыктары» с историей попыток. Используется тот же API, что и в мобильном приложении. Входить могут суперпользователь и одобренный «Курстун башчысы». Администратору также доступен раздел «Окуу курстары». Курстун башчысы видит только «Менин курстарым» и «Окуу курстары» с теми же функциями, что в приложении: курсы, темы, материалы, участники, тесты с дедлайном, запись на чужие курсы. Изменять можно только свои курсы. Проходить тесты в браузере нельзя, только в приложении.

```sh
cd frontend-web
npm install
cp .env.example .env
npm run dev        # http://localhost:5173, /api проксируется на Django :8000
npm run build      # статические файлы в dist/
```

Пока `VITE_APK_URL` и `VITE_IOS_URL` пустые, кнопки скачивания показывают «Жакында». Чтобы выложить APK, положите файл, например, в `frontend-web/public/kutbilim.apk` и задайте `VITE_APK_URL=/kutbilim.apk`, затем пересоберите. В production отдавайте `dist/` и `/api` с одного домена (например, через nginx), иначе понадобится CORS на backend.

## Тесттен өткөн колдонуучулар жана жолдомо

У курстун башчысы в курсе есть раздел «Тесттен өткөн колдонуучулар»: в приложении это вкладка в «Менин курстарым», в вебе пункт бокового меню. В списке пользователи, которые завершили не меньше 2 модульных тестов курса (`REQUIRED_TESTS` в `backend/accounts/referrals.py`). Учитывается последняя завершённая попытка по каждому тесту, провал засчитывается как 0. По каждому видно: учебный номер, Gmail, воинская часть, верные ответы из всех вопросов, оценка (верные / все × 5) и результаты по каждому тесту. Кнопка «Жолдомо жөнөтүү» отправляет пользователю жолдомо, один раз на курс.

Пользователь видит колокольчик в левом верхнем углу главного экрана, на нём красная цифра непрочитанных. Внутри «Билдирүүлөр»: жолдомо с учебным номером пользователя, названием курса и отправителем. При открытии сообщения отмечаются прочитанными.

Миграция: `cd backend && .venv/bin/python manage.py migrate`. Тесты: `.venv/bin/python manage.py test accounts.test_referrals`.

## Модули курсовых тестов

При создании и изменении теста курса курстун башчысы выбирает «1 модуль» или «2 модуль». Поле обязательное: `module` равен 1 или 2. В списке тестов курса и у курстун башчысы, и у пользователя есть переключатель «1 модуль / 2 модуль» с количеством тестов. Кнопка добавления сразу подставляет выбранный модуль. Курсовые тесты, созданные раньше, миграция `0016_course_quiz_module` относит к 1 модулю. Тесты «Командирдик даярдоо» не меняются.

### 24 часа на решение и отмена жолдомо

После того как пользователь завершил второй модульный тест курса, у курстун башчысы есть 24 часа (`DECISION_HOURS` в `backend/accounts/referrals.py`). Рядом с пользователем видно, сколько времени осталось, и две кнопки:

- «Жолдомо жөнөтүү»: жолдомо сразу уходит пользователю.
- «Жокко чыгаруу»: снизу открывается поле «Жокко чыгаруунун себеби». После повторного нажатия «Жокко чыгаруу» отмена с причиной уходит администратору. Пользователь такое жолдомо не получает.

Если за 24 часа ничего не нажато, жолдомо отправляется автоматически («автоматтык түрдө»), и отменить его уже нельзя. Отдельный фоновый процесс не нужен: сервер проверяет сроки при каждом обращении пользователя к колокольчику и курстун башчысы к списку.

У администратора раздел «Жокко чыгарылган жолдомолор» (в вебе пункт меню, в приложении «Башкаруу панели»). Там показаны учебный номер, курс, верные ответы и оценка, причина отмены, кто отменил и когда. Число новых отмен видно на значке.

Миграция `0017_referral_decision_window`, тесты: `.venv/bin/python manage.py test accounts.test_referrals`.

Администратор может удалить запись в «Жокко чыгарылган жолдомолор» кнопкой «Өчүрүү». Запись исчезает только из этого раздела (`admin_deleted`), отмена остаётся в силе: жолдомо не уйдёт автоматически, у курстун башчысы видно «Жокко чыгарылды». Миграция `0018_referral_admin_deleted`.

### Электрондук жолдомо

Пользователь видит жолдомо в «Билдирүүлөр» в виде документа «ЭЛЕКТРОНДУК ЖОЛДОМО». Поля: Окуу номери, Тест тапшырган күнү (дата последнего сданного теста), Тесттин жыйынтыгы («ӨТТҮ», если общая оценка не ниже `PASS_GRADE` = 3, иначе «ӨТПӨДҮ»), Жолдомо берилген күнү, Жолдомонун жарактуу мөөнөтү (`VALID_MONTHS` = 1 ай), Практикалык экзамен тапшыруунун акыркы күнү (дата выдачи + 1 календарный месяц). Внизу показано, сколько дней осталось до экзамена; когда остаётся неделя, срок выделяется цветом. Настройки в `backend/accounts/referrals.py`.

### Каттоо номери, PDF и печать

Каждый отправленный жолдомо получает регистрационный номер (№ 1, № 2, …). Его выдаёт сервер в момент отправки, вручную или автоматически, из счётчика `ReferralSequence`. Номер уникален и не используется повторно, даже если запись удалят. Отменённый жолдомо номер не получает. Миграция `0019_referral_reg_number` пронумеровала уже отправленные жолдомо по дате.

В «Билдирүүлөр» у каждого жолдомо две кнопки:
- «PDF бөлүшүү» создаёт PDF на A4 (`Joldomo-<номер>-<учебный номер>.pdf`) и открывает системное меню «Поделиться»: Telegram, почта, AirDrop, «Сохранить в файлы». Так документ можно перенести на компьютер.
- «Басып чыгаруу (A4)» открывает системную печать.

Шаблон документа: `frontend/src/features/referrals/referralPdf.ts`. Используются `expo-print`, `expo-sharing`, `expo-file-system`, `expo-asset`. После их установки пересоберите development build, Expo Go уже содержит эти модули.
